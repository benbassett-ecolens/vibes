# Stock deal desk

A swarm of four agents that screen equities, hunt setups, read the news, and
size positions for compound growth. Built for learning how a systematic desk
fits together — **not investment advice, and not backtested.**

```
                 ┌──────────────────┐
                 │  market-watch    │  regime → risk budget multiplier
                 └────────┬─────────┘
┌──────────────┐          │          ┌──────────────────┐
│ setup-hunter │──────────┼──────────│  news-sentiment  │
│ screen + tape│          │          │ scores + vetoes  │
└──────┬───────┘          │          └────────┬─────────┘
       │        ┌─────────▼──────────┐        │
       └───────▶│    message bus     │◀───────┘
                └─────────┬──────────┘
                          ▼
                 ┌──────────────────┐
                 │  risk-manager    │  vetoes → Kelly sizing → book limits
                 └────────┬─────────┘
                          ▼
                    recommendations
```

The agents never call each other. Each publishes typed findings to a bus, and
the risk manager reads the blackboard. Adding a fifth agent (insider buying,
options flow, short interest) means writing one class and one topic.

## Quick start

```bash
python -m stock_deal_desk                    # run on the bundled snapshot
python -m stock_deal_desk --show-passes      # explain every rejection too
python -m stock_deal_desk --markdown         # a table to paste into notes
python -m stock_deal_desk --json             # machine-readable
python -m pytest tests/ -q                   # 101 tests
```

By default this runs against `data/snapshot.json`, a **synthetic** fixture
generated by `tools/make_fixture.py` from a seeded RNG. The ticker symbols are
real so the output reads naturally; every number in it is invented and
describes no real company. The reports say so on every run.

For real quotes:

```bash
pip install yfinance
python -m stock_deal_desk --provider yahoo
python -m stock_deal_desk --provider yahoo --universe F,KEY,HBAN,VTRS,AMCR
```

## The four agents

| Agent | Publishes | Job |
|---|---|---|
| `market-watch` | `MarketView` | Benchmark trend, realised vol, breadth → a `RISK_ON / NEUTRAL / RISK_OFF` regime that multiplies every position size (×1.00 / ×0.60 / ×0.25). Takes no view on individual names. |
| `setup-hunter` | `Setup` | Applies the hard screen, then scores the tape: trend stack, 63-day momentum, RSI, position in the 52-week range, volume confirmation. Sets entry, stop and target from **structure** (swing low, 52-week high), clamped into an ATR band. |
| `news-sentiment` | `SentimentRead` | Lexicon scoring with a two-week recency half-life and source weighting (a wire report outranks a company press release). Its more important job is flagging **landmines** — going-concern language, investigations, dividend cuts, short-seller campaigns. |
| `risk-manager` | `RiskDecision` | The only agent allowed to say "size". Hard vetoes first, then fractional-Kelly sizing, then a second pass enforcing book-level limits: total heat, sector concentration, position count. |

## Why this screen is strange, and what it actually selects for

The default screen is the one that was asked for: **high P/E, low share price,
dividend preferred.** It is worth being explicit that this is an unusual
combination, because understanding *why* is most of the value here.

**Share price is not valuation.** A $5 stock is not cheaper than a $500 stock.
Price is market cap divided by share count, and share count is an arbitrary
decision by the company. Screening on low nominal price does not find cheap
companies — it finds small caps, past reverse-split candidates, and names that
institutional mandates exclude. That is a real universe with real (often
higher) expected returns, but it is a *size and neglect* factor, not a value one.

**High P/E and a dividend rarely coexist.** High multiples usually belong to
growth companies reinvesting everything they earn, which is precisely why they
do not pay dividends. So when a screen demands both, it does not find expensive
growth companies. It finds something else:

> **Companies whose earnings have temporarily collapsed, but which are still
> paying.** The P/E is high because the *E* fell, not because the *P* rose.

That is a coherent and genuinely contrarian thesis: cyclicals bought at the
trough. For a cyclical, high P/E at the bottom and low P/E at the top is the
normal pattern, so the textbook "buy low P/E" rule gets the cycle exactly
backwards. The maintained dividend is the signal that management believes the
trough is temporary.

**The same screen also catches every value trap.** Depressed earnings plus a
fat yield is the exact profile of a company two quarters away from a dividend
cut. Nothing in a P/E ratio distinguishes "cyclical trough" from "secular
decline". That is why the risk manager vetoes on:

- **payout ratio > 120%** — the dividend is not funded by earnings and is a cut
  candidate, no matter how attractive the yield looks;
- **news landmines** — an investigation or going-concern paragraph outranks any
  chart;
- **reward:risk below 1.8** — no edge is worth a bad payoff.

In the bundled run, five names pass the headline screen cleanly and are then
thrown out by exactly these rules:

| Name | Yield | Payout | Rejected by |
|---|---:|---:|---|
| `AGNC` | 14.7% | 138% | payout rule — the yield is not funded by earnings |
| `IEP` | 9.6% | 190% | payout rule *and* a fraud / short-seller landmine |
| `MPW` | 8.9% | 162% | payout rule *and* a 0.6:1 reward:risk |
| `WBA` | 4.5% | 118% | news landmine (dividend cut) — its payout squeaks under the cap |
| `NYCB` | 0.8% | 55% | news landmine (SEC investigation, control weakness, CFO exit) |

`WBA` and `NYCB` are the instructive pair: both have payout ratios the risk
rule accepts, and both are caught only because the news agent was reading. A
desk built on fundamentals alone takes them.

**If you wanted cheap instead**, invert it:

```bash
python -m stock_deal_desk --pe-min 0 --pe-max 15 --require-dividend --min-yield 0.03
```

Everything downstream — the tape scoring, the sentiment vetoes, the sizing —
works identically. The screen is the only thing that changes.

## Sizing for capital growth

"Maximise capital growth" has a precise answer. Maximising the expected
*logarithm* of wealth maximises the long-run compound growth rate, and the
fraction that does it is the **Kelly fraction**:

```
f* = p − (1 − p) / b        p = win probability, b = reward:risk
```

`tests/test_sizing.py` verifies this numerically: the analytic `f*` matches a
brute-force search over the growth curve, and betting double Kelly produces
*lower* growth than Kelly while carrying more risk. Overbetting is dominated in
both directions — which is why the desk treats Kelly as a ceiling, not a target,
and bets half of it by default (`--kelly-haircut`).

Three deliberate conservatisms:

1. **Win probabilities are bounded to 0.30–0.62.** An un-backtested score is not
   a probability, and Kelly is famously sensitive to overestimating `p`.
2. **A hard 2% risk cap per trade** sits on top of the Kelly output.
3. **A 10% notional cap per name**, which on low-priced stocks with tight
   structural stops is the binding constraint — the desk reports when this
   happens, because it means the book is running *less* risk than budgeted and
   a gap through the stop is the real exposure.

One honest tension: a dividend preference and capital-growth maximisation pull
in different directions. Growth depends on total return, and in a taxable
account a dividend is a forced, taxable realisation you did not choose the
timing of. The desk therefore treats yield as a *quality and safety* signal —
evidence of cash generation and management confidence — rather than as a return
booster. That is what the `payout_safety` term in `_quality` is doing.

## Configuration

| Flag | Default | Meaning |
|---|---|---|
| `--pe-min` / `--pe-max` | 25 / 150 | "High P/E" band. Above 150 the earnings are too small to be meaningful. |
| `--price-min` / `--price-max` | 3 / 25 | "Low price" band. The floor avoids sub-$3 spreads and delisting risk. |
| `--require-dividend`, `--min-yield` | off, 0 | Dividend was "would be great", so it is preferred, not required. |
| `--equity` | 100,000 | Account size. Drives every dollar figure. |
| `--kelly-haircut` | 0.5 | Fraction of full Kelly to bet. `0.0` deploys nothing. |
| `--max-risk` | 0.02 | Hard cap on equity at risk in one trade. |
| `--max-heat` | 0.06 | Cap on equity at risk across the whole book. |
| `--max-positions` | 8 | Book size. Sector cap (2 names) is set in `RiskConfig`. |

## Layout

```
stock_deal_desk/
  agents/       market_watch, setup_hunter, news_sentiment, risk_manager
  providers/    fixture (offline snapshot), yahoo (live via yfinance)
  bus.py        thread-safe blackboard the agents publish to
  sizing.py     Kelly math — the growth-optimal core
  indicators.py SMA/EMA/RSI/ATR/vol/drawdown, stdlib only
  desk.py       orchestrator: concurrent wave 1, then the risk manager
  report.py     terminal, markdown and JSON renderers
tools/          make_fixture.py — regenerates the synthetic snapshot
tests/          101 tests
```

The core has **no third-party dependencies**. `yfinance` is only needed for the
live provider; `pytest` only for the tests.

## What this is not

- **Not backtested.** No walk-forward, no transaction costs, no slippage, no
  survivorship-bias-free universe. The win probabilities are heuristics mapped
  from scores, not measured hit rates. Until you backtest it, the Kelly output
  is arithmetic on made-up inputs — correct arithmetic, unvalidated inputs.
- **Not investment advice.** It is a teaching scaffold for how screening,
  signal merging, and risk sizing compose.
- **Not a data platform.** Yahoo via `yfinance` is free, best-effort and
  rate-limited; fields go missing and stale routinely. The screen treats a
  missing P/E as "cannot confirm, exclude".
- **The sentiment agent is a lexicon**, not a language model. It is
  deterministic and testable, and it will miss sarcasm, novel phrasing, and
  anything not in its word list. Swapping `_score_headline` for a model call is
  the obvious upgrade; the surrounding contract does not change.

The most useful next step is a backtest harness that replays the fixture
forward bar by bar and measures the *actual* hit rate per score bucket. That
turns `implied_win_probability` from a guess into a calibration, which is what
the Kelly math needs to mean anything.
